## 1 判据的改动（旧判据为什么不能用）

旧判据在 PDF 文本层的**度量盒**上求交。度量盒不是墨迹：

| 字形 | 度量盒（PDF 给的） | 真实墨迹 |
|---|---|---|
| `−` U+2212 | 6.6 × 10.0 pt | **5.0 × 0.52 pt**（一根细横条） |
| `］` U+FF3D | 8.0 × 8.0 pt（1 em） | 1.4 × 6.6 pt（墨迹挤在字身盒左半） |
| `f` 斜体 | 5.5 × 8.5 pt | 墨迹右伸，越过自身推进宽度 |

于是「盒相交」与「墨迹相交」是两回事。**旧判据 125 处里只有 11 处是真叠印。**

v3 改用**字体轮廓的真实墨迹盒**：从 TeX Live 的系统 OTF（与 PDF 内嵌子集同一套轮廓）
用 fontTools 取 charstring 边界，按 span 方向旋转后平移到页面。
取字形必须按 **gid**，不能按 unicode —— PDF 的 ToUnicode 会把多个字形映射到同一
unicode（数字变体 `two.st`、GlyphAssembly 拼装件 `minus.ex` / `uni20D7.lft`），
Fandol 系还是 **CID 键**字体（PDF 的 gid 是 CID，不是字形序号；
实测 U+2013 的 cmap 名是 `cid09910` 而 PDF 报 gid=9910，两者差 1010 位）。
按 unicode 取会取到完全不相干的字形。

判据另做两处修正，都在本报告 §2 里说明了「放宽了什么、因此排除了哪一类」：

1. **改用绝对面积**（≥1 pt²）而不是「占较小盒 45%」。相对判据会漏掉部分压叠：
   p.143 `桥`×`移` 实测交叠 18.1 pt²（全书最大之一）却只占 42%，被漏掉。
2. **区分跨串 / 同串**。跨串（两个不同字符串互相侵入）才是叠印——这正是本项目
   已确认的缺陷形态（图 2-1、图 0-1）。同串内是字体自身的字距与斜体倾斜，
   单列附注。

最后加一道**轮廓真实相交面积**复核（`tools/overlap_ink.py`，0.05 pt 网格采样，
nonzero winding 判定），把「盒相交但笔画不碰」的彻底分开。

## 3 图形级判据：改进与复核

### 3.1 判据

只认**近似矩形**路径：取面积最大的闭合子路径，要求
**面积 / 包围盒面积 ≥ 0.92**；并区分三类：

1. **嵌套**（一个框四边都落在另一个内部，容差 3 pt）→ 正常，排除
2. **相撞**（两框都描边可见、两方向重叠 > 2 pt、非嵌套）→ 缺陷，报告
3. **装饰/背景**（一方只有填充；或一方为长细条，最短边 < 6 pt）→ 排除

### 3.2 为什么不是「精确矩形」

旧判据取所有 drawing 的 `rect` 求交 → 99 处。逐条复核（`tools/audit_rect.py`）：

| 旧判据的 102 处命中（重算） | 处数 |
|---|---|
| 路径**非近似矩形**（面积比 < 0.92） | 102 |
| 其中还叠加「含无描边项」 | 1 |
| 其中还叠加「嵌套」 | 1 |
| **真矩形相撞** | **0** |

全部是菱形（面积比 0.50）、正六边形（0.75）、圆弧、网格线、开口折线这类路径的
包围盒。**99 处全是误报。**

但只认**精确**矩形会漏掉一整类：TikZ `node[draw, rounded corners=1pt]` 画出来是
四段圆弧（面积比 0.998），而**图 0-1 那类缺陷正是圆角节点框**。
本轮复核时发现并补上了这一条。全书被认定为近似矩形的图元 **104 个**。

### 3.3 灵敏度复核

全书近似矩形两两求交（`tools/audit_sens.py`）：

| 分档 | 对数 |
|---|---|
| 不重叠 | 83 |
| 嵌套（容差 3 pt 内，正常） | 10 |
| 一方无描边（背景块，正常） | 1 |
| **部分重叠但较小边 ≤ 2 pt（阈值下）** | **0** |
| **报告** | **0** |

关键一行是「部分重叠但阈值下 = 0」：**全书没有任何一对近似矩形部分重叠**，
要么完全分开，要么完全嵌套。判据不卡在阈值边界上，余量充足。
