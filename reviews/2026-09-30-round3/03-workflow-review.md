以下均在临时副本或独立 PDF 上复现；生产目录、正文和台账未被改动。结构化结果见 [verification.json](verification.json)，复现脚本见 [recheck_review.py](recheck_review.py)。

## R3-W01 · P2 · 无标签或非 tab: 标签的新增表格从来源清点中消失

**定位：** `tools/check_src.py:329–360`，尤其 `355–358`；集合对账 `570–573`。属于 R2-W03 修复不完整。

`scan_tex_tables` 发现 `table` 环境后，只把以 `tab:` 开头的 label 加入集合。因此没有 label 的表、合法但非 `tab:` 命名的表，都不会进入“实际 .tex 表”计数。新增一张没有 `src` 的表后，工具仍可报告“85 张、台账 85 张、集合差异 0”。

| 隔离输入 | 退出码 | 观察 |
|---|---:|---|
| 原始基线 | 0 | 85 PASS |
| 额外无来源、无 label 的表 | 0 | 仍报 85 PASS、差异 0，漏检 |
| 额外无来源、label 为 `review-unregistered` | 0 | 同样漏检 |
| 同一表改用 `tab:review-unregistered` | 1 | 正确识别未登记表 |
| ch01-a 中书页/PDF 页同时加 10000 | 1 | 上轮越界引用漏洞已被阻断 |

**建议及验收：** 先按文件路径和环境起始行清点每一个表环境，再将 label 作为属性和台账关联键。无标签、重复标签、命名不合规范应单列失败，不能从分母删除。验收上面三种新增无来源表均失败，原始基线仍通过；记录“扫描数、已检查数、未检查数”，而非只记录有合规 label 的数。

## R3-W02 · P2 · 空白、待复核等未知状态被汇总为已人工核对

**定位：** `tools/check_src.py:544–545`、`554–557`。

现有逻辑是“包含 `未核对` 则未核对，否则已核对”。空白先被改成“（台账未填）”，随后也进入“已核对”。把任意一张表的 `review_status` 清空，或者填“待复核”，三层报告就从 `已核对 0 / 未核对 85` 变成 `已核对 1 / 未核对 84`。

**影响：** 虽然脚本注明它不代替人工看页面，但汇总会把未知状态升级成已确认的来源证据。当前基线 85 张均标“未核对”，因此这是已复现的状态处理漏洞，并非断言当前台账已有一张错误关闭。

**建议及验收：** 使用明确的状态枚举，例如 `未核对 / 待复核 / 已核对 / 不适用`；只有严格的已核对状态和必要证据字段才进入已完成数。空白、未知值不得升级，可单独计为未知或校验失败。验收空白、待复核、拼写错误、有效已核对状态四组输入，逐项和汇总必须一致。

## R3-W03 · P2 · 没有书签的 PDF 仍被判定书签与后置页眉均 PASS

**定位：** `tools/pdf_probe.py:64–70`、`:122–123`、`:170`。

用三页隔离 PDF 测试，第一页有正文标题但不设置目录书签：结果 `bookmarks_total=0`、`U01_ok=true`、`U02_ok=true`，命令退出码 0。缺少书签时遍历零次，“没有 mismatch”直接被视为通过；最后编号章及后置区块也没有被定位，页眉测试仍能 PASS。给同一 PDF 添加一个有效书签的对照同样通过。

本项目承诺含中文书签，并用此工具辅助验证 U01/U02，因此应能区分“实际检查后通过”与“没有可检查对象”。本轮真实制品确有 143 条书签，未发生书签丢失；问题是将来回归会被漏掉。

**建议及验收：** 对本书配置必要的章级及后置区块清单，并验证实际覆盖；检查前置条件不足时输出 FAIL 或 UNUSABLE。通用模式允许无目录 PDF 时应明确 N/A，不显示书签检查 PASS。验收删除全部书签、删除一个必要后置书签、无编号章、正常目录四种输入，报告检查数、跳过数、必要项缺失数。

## 已验证的流程改善与下一步组织方式

重叠工具的新 `--gate` 在独立相撞矩形上返回 `BLOCK/exit 1`，在分离矩形上返回 `PASS/exit 0`；正常全书为 `blocking=0/candidates=99`。应保留这种分类，不把 99 当作已确认叠印数。来源工具也已经能拒绝页码整体加 10000 的旧反例。

建议后续修复验收按以下顺序组织：

1. **科学计算：** 公式和单位→独立数值→实际送给绘图器的数据；特别是 CPE、Randles。
2. **PDF 实读：** 最终渲染图→标记/条件句→图注→例题；章节锚点检查再加真实查阅任务。
3. **来源状态：** 表环境全量清点→台账关联→页码可达→人工核对记录；不把后一层从前一层自动推导。
4. **关闭记录：** 对每项写修复提交、复现条件、修后结果和证据路径。更新 R2-C09 的关闭判断时引用新的证据；保持原报告历史，不把未经复核的“全部关闭”当作后续输入事实。

这是流程建议，尚未改动生产检查器，也没有启动凭据轮换、重写 Git 历史或发布新 PDF。
