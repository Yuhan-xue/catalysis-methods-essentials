# 交接、来源与发布流程

## R2-W01 · P1 · 交接文档包含明文认证凭据

位置：`HANDOFF.md:67` 的认证行，以及最新发布流程的两处 `curl -u` 示例。本报告不复制账户口令或可还原的编码。

认证行与发布示例把账户与口令直接放在已跟踪 Markdown 中；新同步的提交仍包含这些值。私有仓库的协作者、克隆副本和历史记录仍可读取；把它称作 Basic/base64 不会消除明文暴露。建议由账户管理者轮换已暴露凭据、移除文档中的值，改为说明如何使用凭据管理器或受限令牌，并检查历史中是否需要清理。

验收：正文、示例 URL、提交差异及工具输出中不再出现可用凭据，旧值已失效。仅删除当前一行不能关闭这项。本轮只记录问题，没有修改账户、认证设置或仓库历史。

## R2-W02 · P2 · README 仍描述旧版本，快速开始未进入其声称的严格验收

位置：`README.md:40–58, 70–92` 与 `tools/build.ps1` 的 `-Release` 分支。

README 仍说“23 / 约 37 片、170 页、107 条书签”，并称按用户指示停止推进；最新基线已有 37 个正文分片，本轮构建为 310 页、143 条书签。默认快速开始命令不带 `-Release`，但下方把超宽等发布条件写成该命令的失败条件；实际上这些项在默认 draft 模式不阻断。

建议把“快速预览”和“发布验收”各写一条明确命令，状态表标注生成时间、源码 SHA、模式与产物哈希。静态复制页数和“全部通过”很容易与后续提交分离。验收应由新克隆的读者照 README 运行，得到正确版本和明确的 PASS 含义。

## R2-W03 · P2 · 来源检查接受不存在的页码，且以旧台账决定检查范围

位置：`tools/check_src.py:232–245` 及后续页码偏移、`OCR_TABLE_INDEX` 检查分支。

新增工具解决了来源标注缺失与若干格式问题，这是有效改进，但它没有打开原 PDF 验证目标页。隔离探针保持源码文件不变，只在内存中把 `ch01-a` 的书页与 PDF 页同时加 10000，偏移量不变；**两张表仍 PASS，退出码 0**。故 PASS 不等于页码存在，更不等于该页支持表内数据。

原表号检查只判断 key 是否出现在索引中，没有将索引记录的书页与当前引用页关联。检查目标也来自 `figure_table_list.csv`，没有独立枚举全部实际表格并对账；新增但未登记的表可能不在范围内。

建议把流程拆成三种可区分结论：标注格式合格、目标页可达、内容人工核对。至少加入原 PDF 页数边界、页码区间与原表号对应检查，以及实际表格集合和台账集合差异检查。验收加入不可能页码、错原表号、漏台账三个负例；每类必须失败。人工核对仍需证据图像，不能由偏移一致替代。

## R2-W04 · P2 · 发布模式允许必需的重复引入检查被跳过

位置：`tools/build.ps1:88–103` 和最终 `$fail` 汇总。

新提交已经把 `check_includes.py` 接入构建，真实基线本轮检查通过；本项不再报告“没有接入”。剩余问题是 Python 或检查脚本不可用时，状态为 skipped，而 `$fail` 仅拒绝 FAIL，所以 `-Release` 仍可 PASS。

隔离探针复制构建脚本，使用成功退出的编译器桩和干净日志，不提供检查脚本，真实运行得到 **skipped、PASS、退出码 0**。这只测试门禁分支，不代表实际编译出了一本书。

建议草稿模式可以跳过，但发布模式把必需检查的不可用/异常也判为失败，区分“无问题”与“没检查”。验收包含缺检查器、无 Python、检查器非零退出、正常无重复四种情况。

## R2-W05 · P2 · 重叠扫描器报告命中后仍正常退出，不能单独充当守护门禁

位置：`tools/overlap_check.py` 的 `main()` 结尾与入口。

隔离样例放置两个相交而不互相包含的矩形；扫描器确认 **1 项图形相撞**，但 `main()` 返回 None，入口直接调用 `main()`，没有根据命中抛错或设置失败退出码。README 所说“脚本守护”因此不能由直接执行该脚本实现；发布构建也未消费这份报告。

建议保留扫描模式，并新增明确的门禁模式：先按类别产生结构化结果，确认应阻断的图形碰撞等问题返回非零。文字轮廓、上下标、嵌套框不能简单按总数阻断，要有分类与可审计的例外。验收用无碰撞、相交框、合法嵌套框、数学上下标四个样例验证退出状态和分类。

最新 PDF 的 86 个跨串文字候选尚未逐项确认，本报告不把它们称作 86 处错误。这个发现针对退出行为与流程承诺，和候选总数是否误报是两回事。

## 推荐闭环

```text
同步并固定源码 SHA
  → 来源定位与代数/量纲核查
  → 同时修公式、解释、图和算例
  → 分片检查
  → 全书 Release 构建
  → PDF 导航、图文和实际尺寸抽查
  → 生成带 SHA/哈希的报告
  → 用证据关闭评审条目
```

新增工具不必全部塞进一个巨大脚本，但发布入口应汇总“通过、失败、跳过、待人工核对”，不可将后三种都折叠为 PASS。修复者和复核者都应允许前一判断被反例推翻：本轮 C10-01 台账正是需要重开而非保留结论的实例。
